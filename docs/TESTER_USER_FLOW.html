PART 1

Portal Overview

What is this platform?

A multi-tenant GHG Accounting & Decarbonization Planning portal built by Deepwoods Green. Each client organisation gets their own isolated workspace. The same codebase and backend serve all clients — a client slug and JWT token route each request to the correct data.

ℹ️
Multi-tenant architecture Every page you see is generic. Client name, logo, entities, facilities, and GHG data all come from the database at login time. Nothing is hardcoded for a specific client.

Tech stack (brief)

  • Frontend: React 19 SPA (TanStack Start)
  • Routing: TanStack Router (file-based)
  • State/Data: TanStack Query v5
  • UI: shadcn/ui + Tailwind CSS v4
  • Backend: PHP 8 + MySQL (Hostinger)
  • Charts: Recharts
  • Auth: JWT stored in localStorage

Auth model

  • Token: fl_session_token in localStorage
  • Role: fl_role in localStorage
  • Demo mode: fl_demo_mode=1 — intercepts all API calls with local mock data
  • Must change password: fl_must_change_password=1 forces modal on next page load
  • Orientation flag: decarb_orientation_done — if missing, redirects to /onboard

The five user roles

Role slug Label Organisation Description
sustainability_team ESG Manager / Owner Client Full portal access — primary client role. Can upload data, manage team, view all modules.
client_uploader Data Submitter / Entity Manager Client Data submission only. May be scoped to a single entity.
client_leadership Viewer / Leadership Client Read-only access. No vault, no uploads.
deepwoods_admin Admin Deepwoods All clients, all admin pages. Full operational access.
deepwoods_coordinator Coordinator Deepwoods All clients, coordinator view. No admin panel.

Clicks "Demo portal"

Important: localStorage state matters Browser localStorage persists across sessions. When testing different flows, clear it between runs: DevTools → Application → Local Storage → Clear. Otherwise orientation/setup banners won't reappear.
PART 3

New / Prospective Client Journey

Someone who finds the platform but has no account yet. Their journey ends when Deepwoods converts them into an active client.

Phase 1 — Discovery & Inquiry (No account required)

  1. 1
    Arrive at login page Visits /. Sees two-panel layout: dark left panel (Deepwoods branding, value proposition) and white right panel (login form). Sees "New client?" / "Start your GHG inventory" link at the bottom.
  2. 2
    Navigate to Request Access form Clicks the new client link → routed to /request-access (public, no auth required).
  3. 3
    Fill in the Request Access form Fields: Full name* · Company* · Work email* · Phone (optional) · Company size (optional) · Message (optional). Clicks "Submit request".
  4. 4
    See success state Form replaced by a confirmation message. No email is sent to prospect (backend just stores the row). Deepwoods receives a notification via admin panel.
  5. 5
    Deepwoods follow-up (offline) A Deepwoods admin logs in to /admin → Engagements tab → sees the inquiry. Decides whether to proceed. This step is manual.

Phase 2 — Try the Demo (Optional, no account required)

  1. 1
    Click "Demo portal" on login page Sets fl_demo_mode=1 + a fake session token in localStorage. No server call.
  2. 2
    Explore the workspace Redirected to /workstreams. All data is mock data served from local files. No real API calls are made. The sidebar shows all modules.
  3. 3
    Sign out of demo Clicking "Sign out" clears localStorage and returns to /.
ℹ️
Demo mode intercepts ALL API calls via the authFetch() function. Any action in demo mode (upload, submit, invite) will NOT actually save data. Toasts may still appear as if it worked — this is expected.
PART 4

Deepwoods Admin Journey

The deepwoods_admin role manages all client accounts. They skip the orientation/setup gates and see a cross-client workspace.

Login & navigation

  1. 1
    Log in at / Enters email + password. After login() succeeds, redirected to /workstreams. No orientation check — Deepwoods roles skip it.
  2. 2
    Sidebar — full access Sees all navigation items. The "Admin" link appears at the bottom of the sidebar (only for deepwoods_admin). Entity/FY switcher at the top of the sidebar for switching between client contexts.
  3. 3
    Navigate to /admin 5 tabs appear. Access is guarded by canAdmin permission — non-admin roles see a locked state instead.

Admin Tab 1 — Client Activation

Live data Data comes from useActivationClients() API hook.

What you see

  • Pending clients (amber badge) — newly onboarded, awaiting activation
  • Active clients (green badge) — currently live workspaces

Actions per client row

ActionWhat it doesState
ActivateSets is_active=true in DB. Client can now log in to full workspace.Live
DeactivateSets is_active=false. Client sees PendingActivation screen on next login.Live
InvoiceOpens Invoice modal. Fields: ref number, status (pending/paid/waived), date, notes. Saved to DB.Live
Invite userOpens InviteUserModal. Generates temp password, sends invite email via invite-user.php.Live
GHG SetupAppears for active clients with setup complete. Opens GHG automation setup for that client.Live

Admin Tab 2 — Engagements

Live data Data comes from useClients() API hook.

Actions

  • "New client" button → CreateClientModal: name, slug, currency, reporting period. Creates DB row.
  • Client row expand → see status pipeline. Buttons: "Move to Review", "Mark Report Ready"
  • Relevance Screening button → opens screening UI (session-state only, see Tab 4)

Admin Tab 3 — Submissions Queue

Static mock data 5 hardcoded submission entries. Approve/Reject buttons show toast notifications only — no backend call is made. This tab is not production-ready.

Admin Tab 4 — Relevance Screening

Session state only Shows 15 Scope 3 categories. Click Relevant / Not Sure / Not Relevant per category. Category 3 (Fuel & Energy) is always pre-marked as Relevant. State is lost on page refresh — not persisted to DB.

Admin Tab 5 — Audit Log

Static mock data 9 hardcoded entries (Activation, Invite, Invoice, etc.). No real audit data from DB yet.

⚠️
Admin requires migration 002 and 004 The Activation tab requires DB migration 002_client_activation.sql (adds is_active column). Invoice tracking requires 004_invoice_tracking.sql. Without these, the tab will show DB errors.

PART 6

First-Time Client User Journey

A brand-new client user who receives an invite email and logs in for the first time. Three gates stand between them and the workspace.

Gate 1 — Change Password (if invited via temp password)

  1. 1
    Receive invite email Deepwoods sends invite via admin panel → invite-user.php. Email contains temp password. A flag must_change_password=1 is set in DB for this user.
  2. 2
    Log in at / with temp password On success, fl_must_change_password=1 is set in localStorage alongside the JWT token.
  3. 3
    ChangePasswordModal appears BLOCKING GATE A modal opens immediately. In "forced" mode, the X button is hidden and the modal cannot be dismissed. User must enter current password + new password + confirm new password and click "Update password".
  4. 4
    Password changed Modal closes. fl_must_change_password cleared from localStorage. Proceeds to Gate 2.

Gate 2 — Client Activation Check

  1. 1
    ClientContextGate checks is_active BLOCKING GATE After login, the app calls me.php and then loads ClientContext from context.php.
  2. 2
    If is_active = false → PendingActivation screen Full-page message: "Your workspace is being set up. A Deepwoods team member will activate your account shortly." Sign Out button only.
  3. 3
    If is_active = true → proceeds to Gate 3 Client is active. Moves to orientation check.

Gate 3 — Orientation Tour

  1. 1
    decarb_orientation_done is absent in localStorage SOFT GATE ClientContextGate redirects to /onboard.
  2. 2
    Slide 1 — Welcome Portal overview. Lists 6 modules (GHG Inventory, Action Plan, Progress Tracking, Peer Benchmarking, Green Finance, Document Vault). "Next →" button.
  3. 3
    Slide 2 — Annual GHG Cycle 6-step cycle (Data Collection → Validation → Inventory → Action Planning → Reporting → Review). "Next →" button.
  4. 4
    Slide 3 — Team Roles 4 roles explained (Owner, ESG Manager, Data Submitter, Viewer). "Get started" button.
  5. 5
    "Get started" / "Skip tour" Both set decarb_orientation_done = "1" in localStorage and navigate to /workstreams.

Post-orientation — Setup Wizard (if needed)

  1. 1
    Setup banner on workstreams If setup_complete ≠ "true", a prominent amber banner appears: "Complete your workspace setup". Link to /setup.
  2. 2
    Step 1 — Org Boundary Choose consolidation approach (Operational / Financial / Equity). Choose base year (FY21–FY26). Entity list pre-populated from DB (can add new entities).
  3. 3
    Step 2 — Inventory Boundary Per-entity scope selection: S1 (Stationary / Mobile / Fugitive) · S2 (Grid / Renewable) · S3 (toggle + individual category selection).
  4. 4
    Step 3 — Review & Confirm Summary of all selections with "Edit" links back to steps 1/2. "Confirm & Activate" button.
  5. 5
    Workspace activated! POST to client-setup.php. Sets setup_complete = true in DB. Clears ClientContext cache. Success screen: two CTAs — "Start data collection" → /submissions or "Go to workspace first" → /workstreams.

Golden-Path Test Cases

ℹ️
Run these tests in order. Each one covers a distinct user journey. Before each test, clear localStorage via DevTools → Application → Local Storage → Clear All, unless told otherwise.
TC-01Unauthenticated visitor — Request Access flow Public
Precondition
No localStorage. Migration 003 (client_requests table) must be applied.
Steps
  • Navigate to site root (/). Verify login page appears with both panels visible.
  • Click "New client?" / "Start your GHG inventory" link at bottom right.
  • Verify redirect to /request-access. Verify page is accessible without login.
  • Fill in all required fields (name, company, email). Leave optional fields blank. Submit.
  • Verify success state appears (form replaced by confirmation message).
  • As deepwoods_admin, log in → /admin → Engagements tab → verify the inquiry row appears.
Pass criteria
Success state shown. Request visible in admin Engagements tab.
TC-02Demo mode — full workspace exploration Demo
Precondition
No localStorage. No account required.
Steps

  • Sign out (sidebar or profile menu). Verify return to / and localStorage cleared.
Pass criteria
All pages load with mock data. No API errors. Logout clears localStorage.

Security & Access Boundary Tests

🔒
Do NOT test these on production with real credentials you don't own. These tests verify that access controls are enforced. Use test accounts only.

Authentication boundary tests

#TestExpected result
S-01 Navigate to /workstreams without any localStorage token. Redirect to / login page. No workspace content shown.
S-02 Set a fake/expired JWT in fl_session_token localStorage. Navigate to /workstreams. me.php returns 401. User logged out automatically. Redirect to /.
S-03 Copy a valid token from one user's browser. Use it in another browser as a different user. The token is valid for the original user only. Data returned belongs to that user's client.
S-04 Manually set fl_role=deepwoods_admin in localStorage while using a client_leadership token. Navigate to /admin. The backend API still enforces role checks. Admin API calls should return 403. The frontend might show the admin UI but all data fetches should fail.

S-08 Log in as client_leadership. Navigate to /vault. LockedState or redirect. Vault content not visible.

Bugs — Active

CT-1 Legacy DB roles (featherlite_team, featherlite_leadership, automation_demo) not yet renamed to generic role names. All auth-gated pages for legacy users Run migration 001. Until then, legacy role users may see incorrect access.

Pre-test checklist for a clean test environment

  • Run all 4 DB migrations (001–004) on the test database.
  • Configure backend/config.php: admin_email, platform_base_url.
  • Set VITE_GHG_WEBAPP_URL in .env.local if testing Notifications (optional).
  • Create at least one inactive test client and one active test client in DB.
  • Create test users for each of the 5 roles.
  • Ensure one test user has must_change_password=1 to test TC-03.
  • Configure SMTP (or test email) for invite and password reset flows.
  • Clear browser localStorage between test runs (DevTools → Application → Local Storage → Clear All).
  • Verify CORS proxy (ghg-proxy.php) is deployed to public_html/ separately from the app bundle.
