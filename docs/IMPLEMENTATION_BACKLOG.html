01

Auth & Role Foundation

"Before anything else works, auth must work."

1 day No deps C-1 · A-3

Business objective

No authenticated user is silently logged out. Administrators can create client accounts with the correct platform roles through the API.

Technical objective

Remove featherlite_team, featherlite_leadership, automation_demo from the users.role ENUM. Update users.php $validRoles. Add client_id to user INSERT.

Definition of Done

  • The role ENUM contains exactly the 5 generic platform roles
  • All existing users holding legacy roles are migrated before the ALTER runs
  • users.php POST accepts exactly sustainability_team | client_uploader | client_leadership | deepwoods_admin | deepwoods_coordinator and rejects all others with 400
  • A new user with any valid role can log in without silent logout
  • Featherlite's existing users continue to work after migration

Files affected

  • database/schema_combined.sql— ALTER TABLE ENUM definition
  • database/migrations/001_migrate_legacy_roles.sqlNEW
  • backend/api/users.php— $validRoles + client_id in INSERT

API changes

  • users.php:25 — $validRoles updated to 5 platform roles
  • users.php POST INSERT — add client_id; validate it exists in clients
  • All other endpoints: no change (they already use session client_id)

Database migration

-- Step 1: migrate existing legacy-role users BEFORE the ALTER
UPDATE users SET role = 'sustainability_team'
  WHERE role IN ('featherlite_team', 'automation_demo');
UPDATE users SET role = 'client_leadership'
  WHERE role = 'featherlite_leadership';

-- Step 2: remove legacy values from the ENUM
ALTER TABLE users
  MODIFY COLUMN role
    ENUM('sustainability_team','client_uploader','client_leadership',
         'deepwoods_admin','deepwoods_coordinator')
    NOT NULL DEFAULT 'sustainability_team';

UI changes

None — role guards in _app.tsx ROLE_META resolve correctly once the ENUM is fixed.

Testing checklist

  • Featherlite users with legacy roles can log in after migration
  • POST /api/users.php with role=featherlite_team → 400
  • POST /api/users.php with role=sustainability_team + valid client_id → 201
  • New sustainability_team user logs in, no silent logout
  • New client_uploader user logs in, no silent logout
  • ROLE_META in _app.tsx resolves correctly for all five roles

04

Consolidated Entity Logic

"Any client's consolidated entity must work, not just FL."

0.5 day Needs E-1 C-2

Business objective

All decarbonisation and credits data endpoints return correct results for any client, regardless of how their consolidated entity is named.

Technical objective

Replace the hardcoded $entity !== 'FL' check in four PHP endpoints with a DB-driven consolidated entity lookup per client.

Definition of Done

  • All four endpoints determine consolidated status by querying client_entities WHERE client_id = ? AND is_consolidated = 1
  • Passing a consolidated entity code for ANY client returns all-entity data
  • Passing a non-consolidated entity code returns only that entity's data
  • Featherlite's existing behaviour is unchanged (FL still returns all-entity data)
  • The string literal 'FL' does not appear in any of the four files

Files affected

  • backend/api/decarb/actions.php
  • backend/api/decarb/assets.php
  • backend/api/credits/irec.php
  • backend/api/credits/grid-mwh.php

Database changes

None — uses existing client_entities.is_consolidated column.

API changes — pattern applied to all 4 files

// Before:
if ($entity && $entity !== 'FL') { /* apply entity filter */ }

// After:
$consStmt = $pdo->prepare(
    'SELECT code FROM client_entities WHERE client_id = ? AND is_consolidated = 1'
);
$consStmt->execute([$clientId]);
$consolidatedCode = $consStmt->fetchColumn() ?: null;

if ($entity && $entity !== $consolidatedCode) { /* apply entity filter */ }

UI changes

None — same request/response shape.

Testing checklist

  • Featherlite: ?entity=FL → all-entity data
  • Featherlite: ?entity=FP → FP-only data
  • Client B: ?entity=<consolidated> → all-entity data
  • Client B: ?entity=<leaf> → filtered data
  • grep -r "'FL'" backend/api/decarb/ backend/api/credits/ → zero matches
  • Same four tests pass for assets.php, irec.php, grid-mwh.php
