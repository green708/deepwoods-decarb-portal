# src/ — TanStack Start Frontend

This is the TanStack Start (React 19) frontend root. Vite and TanStack Router
expect files in this directory at specific paths — do not rename or move this
folder without updating `vite.config.ts`, `tsconfig.json`, and all path aliases.

## What belongs here

- `routes/` — Page components. Every `.tsx` file here becomes a route.
- `components/` — Reusable UI components and shadcn/ui primitives.
- `lib/` — Frontend utilities, API hooks, auth, context providers.
- `data/` — Platform-wide constants and type interfaces.
- `hooks/` — Generic React hooks.
- `styles.css` — Global styles and Tailwind CSS entry point.
- `router.tsx`, `server.ts`, `start.ts` — TanStack Start entry points.
- `routeTree.gen.ts` — Auto-generated by TanStack Router — do not edit manually.

## What does NOT belong here

- Client-specific data (GHG inventory numbers, facility lists, targets) — these live in MySQL, accessed via hooks in `lib/api.ts`.
- Server-side logic — use `backend/api/` PHP files for all API endpoints.
- Static binary assets — use `public/` for images, fonts, and documents.
- Test files — use `tests/`.

## Conventions

- **Path alias:** `@/` maps to `src/`. Use `@/components/portal` not `../../components/portal`.
- **Data fetching:** Always use React Query hooks from `src/lib/api.ts`. Never import from `featherlite.ts` or any client-specific data file.
- **Entity context:** Get the active entity from `useEntity()` and client data from `useClientContext()`. Never hardcode entity codes.
- **No hardcoded client names** — see `CLAUDE.md` for the full no-hardcoding rule.

## Route file naming

TanStack Router uses file-based routing with a dot notation:
```
_app.dashboard.tsx    →   /dashboard  (inside _app.tsx layout)
_app.submissions.tsx  →   /submissions
index.tsx             →   /  (login)
```
